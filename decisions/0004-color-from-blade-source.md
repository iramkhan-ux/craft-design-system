## Context

Decision 0001 took the color values from the Blade Figma file (Community copy). A comparison with Blade's source code showed the two differ: of 222 primitives, 115 had different values and 131 source primitives were missing, and of 263 semantic tokens about 186 differed in light and in dark. The designer ruled that **Blade source code is the final source of truth**, and chose to rebuild color from it with the full source set.

Source: `razorpay/blade`, commit `e914cf6a843193dc5f259aae27027c1dbb3544ea` (2026-09-10), files `packages/blade-core/src/tokens/global/colors.ts` (primitives) and `packages/blade-core/src/tokens/theme/bladeTheme.ts` (semantic tokens, `onLight` and `onDark`).

## Decisions

| # | Decision |
|---|---|
| 1 | Blade source code is the truth for every Craft foundation. When the source and the Blade Figma file differ, the source wins. |
| 2 | Primitives: all 353 colors in the source, in 11 chromatic families (azure, emerald, crimson, cider, sapphire, sea, cloud, forest, orchid, magenta, topaz) and 8 neutral families (blueGrayLight, blueGrayDark, ashGrayLight, ashGrayDark, white, black, whiteSolid, blackSolid). Names are the source names. |
| 3 | Semantic tokens: all 435 in the source theme, light and dark: interactive (175), data (145), surface (52), feedback (40), popup (20), overlay (2), transparent (1). This includes the data chart colors. |
| 4 | Each semantic token points to the one primitive the source points to. Five tokens are raw because the source writes `transparent` or a literal value: `surface.background.primary.faint`, `.moderate`, `.strong`, `surface.background.accent.intense`, and `transparent`. |
| 5 | Values are stored exactly as the source writes them (`hsla(218, 89%, 51%, 1)`). Nothing is converted or rounded in the master record. Figma and the parity checksum use the 8-bit hex and whole-percent alpha derived from each value. |
| 6 | Removed because the source has no such colors: `interactive.hover.subtle`, `interactive.hover.intense` and the five `elevation.*` colors from 0001. Elevation colors come back with the elevation foundation, from the source shadows. |
| 7 | Figma: the color collections are rebuilt from the new tokens in natural order. The old Figma state stays recoverable through the saved version of checkpoint `color-foundation-v1`. |

Decisions 1, 4, 5 and 6 of 0001 still hold. Decision 7 of 0001 (docs) is replaced by `docs/color.md`, which lists primitives first and then the semantic tokens.

## Exceptions and oddities

- The source has no deprecated tokens in the theme file, so nothing is left out.
- Neutral alpha steps are named by the source as step plus alpha, for example `blueGrayLight.a912` (the 900 color at 12%). The Figma file used shorter names (`a25`, `a50`). The source names are used.
- 163 of the 353 primitives are not used by any semantic token. They are kept for fidelity with the source.
- `blueGrayLight.50` and `blueGrayLight.100` have the same value in the source.
- Light and dark `transparent` use different literal colors in the source: `hsla(0, 0%, 100%, 0)` and `hsla(210, 6%, 13%, 0)`.
- The Blade repository updates its tokens from its own Figma file. The Community copy is a different, earlier state, which is why the two disagree.

## Rules confirmed

No new guardrails. Guardrail 5 of `skills/guardrails/color.md` (a new color token points directly to one primitive) is unchanged. The five raw tokens above follow the source.
